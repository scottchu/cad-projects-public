# Kage preview launcher brief

## Frozen design contract

- Project and iteration: repository-wide preview launcher with Kage consumer evidence, recorded in `projects/kage/docs/iterations/2026-08-23-preview-launcher` (`KAGE-PREVIEW-001-R3`).
- Repository baseline: `4ead3fba0a9aa964a46a3dc8e963b3575563183d` on `codex/kage-retire-legacy-folders`; delivery target is pull request #5, then `main` when its independent gates pass.
- Parent migration fingerprint: `projects/kage/manifests/candidate.sha256` SHA-256 `81b98d4c043560512076b2599b7200e3ffe90a6e84a5300b25ac9941c5e57fb0`. Its closure must ignore generated `__cadgen__` directories as runtime debris.
- Kage consumer artifact: imported locked reference `projects/kage/references/locked-direct-gear/p3_v3_direct_gear_race_assembled.step`, SHA-256 `dea274f64bdc841e77d75fda9d4e0638a9627a599d13295cb78b0ec1bd6997a7`; it remains a historical reference, never restart CAD acceptance.
- User outcome: a repeatable repository-level `bin/preview-cad [--sha256 EXPECTED] <workspace-dir> <file-relative-to-workspace>` launcher, runnable from any cwd, which restores a healthy current CAD Viewer on port `3245`, builds the requested supported artifact, and prints local and Tailscale review URLs with a cache-busting token. It is a standalone POSIX-shell executable, not a Python console script plus wrapper: its work is process discovery, environment construction, HTTP probing, and safe signaling; adding a packaged Python entry point would create unnecessary installation and wrapper coupling. Kage is one documented consumer: `bin/preview-cad --sha256 dea274f64bdc841e77d75fda9d4e0638a9627a599d13295cb78b0ec1bd6997a7 projects/kage/references locked-direct-gear/p3_v3_direct_gear_race_assembled.step`.
- Generic input contract: resolve both operands to canonical absolute paths before any listener probe or process action. `workspace-dir` must be an existing directory; `file-relative-to-workspace` must be a nonempty relative path whose resolved regular file remains contained by that workspace (no `..`, absolute path, or symlink escape). Pass the resulting generic relative file to the Viewer and allow only installed Viewer-supported artifact/generator source types. `--sha256` is optional for generic use; when supplied it must be exactly lowercase SHA-256 and match the resolved file before process action. Kage documentation and validation must always supply the locked STEP checksum.
- Viewer selection: dynamically select the newest installed `text-to-cad/cad/*/skills/cad-viewer` runtime containing `scripts/viewer/package.json`; never hardcode a cache version. Invoke its viewer with `VIEWER_CAD_PYTHON=<repository-root>/.venv/bin/python`. Locate `npm` first on `PATH`, then use `/Applications/ChatGPT.app/Contents/Resources/cua_node/bin/npm`; fail clearly if neither works. Do not use a project-local virtual environment.
- Launch context: start Viewer with current directory equal to the validated workspace directory, never repository/project root by default. This preserves generic behavior and prevents a project-local `cadgen.py` outside the requested workspace from shadowing the real package. The Viewer URL workspace and `file` values are derived only from the validated arguments.
- Listener safety: probe port `3245` before any signal. A listener is reusable only when `GET /__cad/server` returns JSON with `app == "cad-viewer"` **and** the exact generic workspace review-page URL returns HTTP 200 with the installed Viewer shell marker `id="root"`. Capture this accepted pre-existing listener as `CURRENT_TOKEN = PID + PS start time + normalized command`; treat malformed/404/static responses, a mismatched app, missing Viewer shell, or an unusable build endpoint as unhealthy/stale. Never signal a listener that is not positively identified as CAD Viewer. Immediately before a stale-listener `TERM`, re-read the exact listener token and reconfirm API/page identity; PID, start-time, command, or identity drift cancels cleanup. After that `TERM`, transient API loss is expected rather than identity drift: boundedly wait only for the exact token to disappear or the port to become free, then restart. Never send `KILL` to any pre-existing listener.
- Owned-startup safety: start Viewer in a new process group; immediately capture its stable group-leader token `PID + PS start time + normalized command`. If its post-start health/build fails, re-read the exact leader token before signaling. If absent or drifted, send no signal. If matched, send at most `TERM` to that verified owned process group, then boundedly observe; never send `KILL` to a failed-start group because PGID reuse cannot be ruled out.
- Health and readiness: after reuse or restart, first require `GET /__cad/server?dir=<absolute workspace URL path>` to identify `cad-viewer`; then GET the exact generic workspace review-page URL and require HTTP 200 plus `id="root"` before posting the artifact build. `POST /__cad/artifact?dir=<absolute workspace URL path>&file=<encoded validated relative file>` must return HTTP 200 and JSON `ok != false`, `state == "ready"`. Poll boundedly only for an explicitly returned `generating` state. Immediately after artifact-ready, re-read the listener token and require exact equality with accepted `CURRENT_TOKEN` before printing either URL. Any `error`, malformed JSON, missing shell marker, token replacement, wrong status, or timeout fails with no success stdout.
- Output: success stdout contains exactly one human-readable local URL and one Tailscale URL, both with the same URL-encoded workspace/file and `cb=<token>` query parameter. `TAILSCALE_HOST` may override the default host `mac-mini.duckbill-ionian.ts.net`; absent `tailscale`/host reachability is reported as a separate warning only after local readiness. Stderr carries diagnostics; nonzero exit means no ready preview.
- Test seam: shell tests must be hermetic and not touch port `3245`, real processes, the Viewer cache, the network, or the reference cache. Inject command locations, HTTP probe/build responses, listener identity/PID metadata, PS leader tokens, clock/sleep, process actions, and capture of launch cwd/environment through environment variables or executable stubs. Tests must deterministically cover robust whitespace/semantic-version discovery of the newest Viewer, current-runtime provenance, bundled-npm PATH fallback, root-Python/workspace cwd, containment/checksum failure before process action, healthy reuse, identified-stale restart, PID drift cancellation, non-Viewer listener refusal, URL encoding/cache buster, artifact-ready success, and failure for build error/timeout. Regressions must prove: API identity healthy plus artifact `ready` but review page `404 Not found` restarts only the identified Viewer; owned leader absent/drift causes no TERM/KILL; matched owned leader receives TERM only; no unconditional negative KILL path exists; final token replacement fails with no URL stdout; and post-TERM API loss plus exact-token disappearance/port release permits restart. Kage consumer validation must invoke the generic CLI with its checksum.
- Scope: implementation may add root `bin/preview-cad`, root `tests/test_preview_cad_launcher.py`, root user documentation and any contractually required architecture note, Kage consumer README/iteration records, the minimal Kage integrity-test/manifest updates excluding `__cadgen__`, and candidate provenance. Kage owns no bin wrapper or launcher test. It must not modify CAD/reference source or artifact bytes, legacy trees, state/next files, or stop a live Viewer during hermetic tests.

## Acceptance targets

The repository tool is a local operational aid, not CAD, slicer, or physical validation. Generic-tool acceptance requires the root hermetic contract tests and documented CLI. Kage-consumer acceptance additionally requires Kage integrity/manifest checks and an independently witnessed checksum-pinned launch/build/fetch of the locked STEP. CAD/source remains no restart candidate; artifact/slicer remains migration-only; physical print/assembly remains pending.

### Task details

**001 design.** Reads the frozen baseline, continuity/policy records, Viewer skill/runtime contract and locked-reference identity. Writes only this iteration's `BRIEF.md`, `DESIGN.md`, `VALIDATION.md`, `REVIEW.md`, `HANDOFF.md`, and `iterations/CURRENT`. It must not implement, launch, approve, or alter acceptance labels. Stop on an ambiguous listener-ownership or runtime contract.

**002 implementation.** Reads the frozen generic R3 contract, exact Viewer runtime, repository root workspace configuration, Kage consumer artifact/hash, and focused test conventions. It exclusively writes root launcher/test/docs plus bounded Kage consumer/integrity/provenance paths; it must remove/supersede the invalid Kage-local launcher rather than retain a wrapper. It must not change CAD/reference artifact bytes, continuity indexes, branch/PR, or real listeners. Deliver a candidate SHA-256 path/content manifest, executable mode evidence, generic and Kage-consumer test commands/results, and a self-check receipt. Stop on missing root `.venv`, no selected Viewer runtime/npm, contract ambiguity, invalid user path/checksum, failed review-page shell probe, token/PID drift, or a need to signal an unverified process group. It must have no KILL path for failed-start or pre-existing Viewer cleanup.

**003 critic.** Read-only against the exact candidate except its designated `REVIEW.md` finding record. Challenge arbitrary process killing, PID reuse, shell quoting/path traversal, cache-version discovery, run-directory/Python shadowing, endpoint/build semantics, URL encoding, and test isolation. It cannot repair, launch, or approve. Stop on candidate drift or any missing candidate manifest.

**004 validator.** Independently run the declared test suite and integrity closure, inspect source shell syntax and executable bit, and conduct a controlled real launch only after confirming the port listener identity. Record exact commands/statuses in `VALIDATION.md`; do not alter sources, reuse an implementation receipt as proof, or claim physical/CAD acceptance. Stop on candidate drift, non-Viewer listener, unavailable local prerequisites, or a real-process action outside the contract.

**005 formal review.** Audits 002--004 identity separation, exact candidate provenance, requirements/contract coverage, and dispositions. It issues a verdict only; it cannot repair or self-review an implementation. Stop on missing upstream receipt, candidate mismatch, or unresolved critical/high safety finding.

**006 root delivery.** Verifies the accepted candidate and clean working tree, updates PR #5 concisely, and merges only after the formal verdict and local gates. It must preserve the locked-reference/non-acceptance language and stop rather than merge for a safety finding, manifest mismatch, or external delivery failure.
