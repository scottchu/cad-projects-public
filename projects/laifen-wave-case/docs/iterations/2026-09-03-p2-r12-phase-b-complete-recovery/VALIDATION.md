# VAL-GCS-R12-01 independent validation

**Verdict: FAIL.** The exact R12 candidate fingerprint `51727da73c72db6e391f4f83014a54076dc2ffbdc5bc617f753c72a8fc1a2221` verifies, and the prescribed Phase A, Phase B, renderer, compact-audit, and browser suites pass. This receipt covers the frozen browser visual-intent candidate only. It is not CAD, OpenSCAD, STEP/export, slicer, printability, fit, strength, drainage-performance, or physical acceptance.

## Blocking findings

### R12-V01 — P1 — 32 parameter witnesses are visually inert

All 84 official A/B witness pairs change their descriptor hash, but only 52 change any byte in `renderMainSvg`, `renderDetail`, or `renderComparison`. The renderer turns `Object.keys(d.targets)` into static marker circles and does not consume each target's changing effect. The official renderer test checks target presence, so it passes while these parameter changes remain invisible.

The 32 no-delta witnesses are:

- container: `wall`, `floor`, polygon `sideCount`, `cornerRoundness`, and `rotationDeg`;
- screw: `pitch`, `turns`, `leadRunoutTurns`, `formHeight`, and `radialClearance`;
- bayonet: `lockAngleDeg`, `lugCount`, `capture`, `rampRise`, and `radialClearance`;
- surface: `minWall`, `fadeMetric`, and `keepout`;
- drains: `linked`, bottom `ringRadius`, and top `ringRadius`;
- label: `angleDeg`, `axialFromTargetEnd`, `patch`, and `patchMargin`;
- attachment: `presentation`, `attachHalf`, `mountAngleDeg`, `openingWidth`, `pivotClearance`, `keyringHoleDiameter`, and `bridgeSpan`.

The polygon alias is direct: valid side counts `3, 4, 5, 6, 7, 8, 12` produce seven distinct descriptor hashes and one identical rendered visual hash, `07d38c0f4b102586c2ef3a98a9e5cdb79dd025f3179801831cff7b9cc567873b`. Browser interaction independently reproduced identical visuals for 3 through 12 sides in all six engine/viewport combinations. Screw pitch, bayonet angle, label angle/axial position, and attachment opening width were also unchanged in all six combinations. This blocks the requested parameter-sensitive visual generator.

### R12-V02 — P1 — Basic/Advanced disclosure does not hide advanced controls

At the default state the schema has 27 active fields: 14 Basic and 13 Advanced. Every tested browser displayed all 27 before the toggle and all 27 after it. The button's text and `aria-pressed` state change, but the controls do not. `app.mjs` sets `hidden` on advanced `.field` labels; `style.css` assigns `.field { display:grid }`, overriding the user-agent hidden display rule. This fails the grouped Basic/Advanced control requirement in Chromium, Firefox, and WebKit on desktop and mobile.
