## Blocking findings

### R13-V01 — P1 — Generic hash witnesses manufacture the 84/84 result

`render/renderer.mjs` defines `group(field, value, ...)`, hashes `JSON.stringify(value)`, and maps that hash to an arbitrary triangle's width, rise, and HSL color. `witnesses(...)` emits these groups as `data-field-target` nodes. The prescribed observability test extracts the first such node for each field and asserts that its SHA-256 changes. This proves the local hash glyph changed, not that the required semantic geometry/style/text changed.

The independent ordered audit inspected all 84 official A/B pairs. The first target for **83/84** rows is one of these generic `field-witness` groups; only `container.splitPercent` first resolves to its justified metadata span. This directly violates R13-04's exclusion of generic target/effect-hash changes and R13-05's semantic-target rule. It also repeats the mechanism class that R13 was created to recover from in R12.

### R13-V02 — P1 — Eleven fields own duplicate targets

Only **73/84** official rows have exactly one `data-field-target` node in both A and B renders. The remaining 11 are duplicated across the generic witness grids and a second surface or metadata span:

- `surface.reliefMode`, `surface.depth`, `surface.minWall`, `surface.keepout`, `surface.quilt.pillowHeight`;
- `label.openScadFontFamily`, `label.target`, `label.angleDeg`, `label.axialFromTargetEnd`;
- `attachment.attachHalf`, `attachment.mountAngleDeg`.

This violates the frozen ownership rule that every active coverage row owns exactly one visible target. The prescribed target test uses `assert.match`, so it proves presence while missing duplicates.

### R13-V03 — P1 — Required semantic geometry remains inert or aliased

After removing every generic `field-witness` group and all `data-*` bookkeeping, only **73/84** official witness pairs change their declared semantic surface. The 11 no-delta rows are:

- `container.floor`;
- `closure.matchPatternClosed`, `closure.bayonet.radialClearance`;
- `surface.minWall`, `surface.keepout`;
- `ventDrain.linked`;
- `label.axialFromTargetEnd`;
- `attachment.attachHalf`, `attachment.mountAngleDeg`, `attachment.common.pivotClearance`, `attachment.common.bridgeSpan`.

The exhaustive polygon silhouette itself is unique for all 30 side counts from 3 through 32. The required roundness/rotation matrix still fails: for each of sides 3, 4, 5, 6, 8, 12, and 32, the six `(roundness 0/0.45/1) × (rotation 0/31)` cases produce only five unique section paths. At roundness `1`, rotations `0` and `31` serialize the same path. The prescribed test passes because the rotation hash witness changes even when the section silhouette does not.

The categorical geometry audit strips witnesses and captions before hashing. Screw/bayonet, the four end profiles, four envelopes, three relief modes, three label modes, six attachment states, and four drain modes remain distinct. Surface patterns produce only **9/10** geometry hashes: `blunt_diamond` and `recessed_diamond` have identical surface-map geometry, with only their caption/hash witness distinguishing them. This fails the required family-specific surface field.

## Passing runtime behavior and limits

The prescribed browser test independently reran in this validation session and passed Chromium, Firefox, and WebKit at desktop `1280×900` and mobile `390×844`. Each context had 14 visible Basic controls and 13 hidden Advanced controls initially, then 27 visible controls after toggling Advanced. Hidden inputs had computed `display:none`; the page retained the exact conceptual-only and fit-to-view disclosures; invalid OD cleared the complete sheet and exposed the linked alert; and no page error or horizontal page overflow was observed.

Those runtime passes do not waive the earlier semantic-target failures. Per the frozen stop rule, no delivery, route, or later acceptance gate may proceed on this candidate.
