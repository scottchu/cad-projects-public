## Main lifecycle contract

Use the existing monotonic `job` number; no new scheduling framework is needed.

1. Make `stop(message)` synchronously increment `job` **before** clearing timeout, terminating/nulling worker, disposing mesh and invalidating href. Every stop is terminal for its old handlers, including stop on success, verification failure, compiler error and a replacement Generate. Remove the redundant `job++` from Cancel, Reset and timeout callers. Preserve their status, stale, toast and focus behavior.
2. Generate calls `stop()` first, then captures `const id=job` synchronously before any `await`. Validate and freeze `snap` as now. After `await identityReady` and again after `await identity(...)`, return unless `id===job`. This prevents a reset/cancel/new Generate during hashing from creating an obsolete worker. Keep Cancel's current visible enable timing.
3. Construct a local `const jobWorker=new Worker(...)`, then assign global `worker=jobWorker`. The first statement governing every received event must reject unless **`id===job && worker===jobWorker && d.id===id`**. Apply this before stage/log/error/result handling. A stage/log/error from an old worker must not overwrite a new job or dismiss its output.
4. For an active result, additionally require exact `identity===key`, `sourceHash===sourceHash` and `lockFingerprint===lockFingerprint` against captured expected values. A wrong tuple stops that job, blanks preview/download and uses the existing verification-failure toast. No missing field, wrong type, legacy identity or partial tuple is accepted. Wrong message id is ignored without killing the legitimate active job.
5. A correct active result may call terminal `stop()` and synchronously install its bytes/mesh/download exactly as now. Any duplicate result then fails the active guard. Keep exact transferred bytes in the Blob and full identity in filename; do not reserialize STL.
6. Remove the separate Generate click-listener/polling watchdog. Arm the same **180000 ms** timer inside the successful worker setup, with the same captured job/worker guard before terminal timeout handling. Record its boundary as job dispatch, not a new performance contract. No previous timer can stop a newer job. The private acceptance ceiling remains **60000 ms** from worker construction, including probe/runtime/compile/transfer.

This is an explicit small lifecycle delta, not permission to rework rendering, stale semantics, error copy or the worker. The regression must reproduce the old failure and pass the candidate with the same correct payload. Merely nulling `onmessage` is insufficient as the proof because the regression retains the old callback itself.
